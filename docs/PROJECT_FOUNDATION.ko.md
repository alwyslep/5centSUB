# 5centSUB 프로젝트 기반 계획

## 목표와 성공 기준

- 권리를 보유하거나 처리를 허가받은 일본어 영상에서 한국어 자막을 만든다.
- 4시간 입력 영상의 전체 클라우드 비용을 미화 5센트 이하로 유지한다.
- 결과물은 표준 SRT이며, 자막 시간 범위와 문법을 자동 검증한다.
- 각 작업은 입력 식별자, 단계별 상태, 실패 사유, 사용량, 비용을 남긴다.

5센트는 목표치가 아니라 릴리스 차단 조건이다. 실제 사용량에 따른 비용 계산이
가능해지기 전에는 이 목표를 달성했다고 주장하지 않는다.

## 기존 프로젝트에서 얻을 기준

| 참고 프로젝트 | 사용할 근거 | 이 저장소에서의 취급 |
| --- | --- | --- |
| WhisperJAV-Cloud | 무음 구간을 활용한 입력 축소, 원본 시간축 역매핑, 컴팩트 자막 전송 형식, 비용 측정 실험 | 동작 요구사항과 실험 방법만 참고 |
| javstt-cloud | 클라우드 전사 작업의 설정, 취소, 재개, 오류 진단, 사용량 기록, SRT/ASS 회귀 검증 구조 | 공개 가능한 새 구현의 구조 참고 |
| javtrans | 일본어 판별, 한국어 번역 품질 검사, SRT 정규화 및 회귀 사례 | 품질 계약과 테스트 시나리오 참고 |
| javstt | 구세대 구현의 기능 목록과 이전 측정 기록 | 기능 후보 확인용 참고 |
| pyvideotrans | 지원 서비스와 사용자 경험의 참고 사례 | GPLv3 코드·자산을 가져오지 않음 |

WhisperJAV-Cloud, javstt-cloud, javtrans에는 저장소 최상위의 공개 재사용
라이선스가 확인되기 전까지 코드를 복사하지 않는다. 가져올 후보가 생기면 파일별
저작권자, 라이선스, 필요한 고지, 수정 내역을 먼저 기록한다.

## 처리 경계

새 구현은 로컬 ML 모델, GPU 추론, 사용자 컴퓨터의 음성 인식을 사용하지 않는다.
미디어 준비를 로컬 FFmpeg로 허용할지, 관리형 클라우드 작업으로만 처리할지는
아직 결정하지 않았다. 이 결정은 비용, 개인정보, 업로드 시간, 배포 방식에 영향을
주므로 첫 구현 전에 확정한다.

API 키, 원본 영상·오디오, 생성 자막, 요청·응답 본문, 사용량 기록은 Git에 넣지
않는다. 테스트는 합성 또는 명시적으로 재배포 가능한 짧은 자료만 사용한다.

## 단계별 진행 순서

### 0. 기반 문서화

이 문서, README, 저장소 규칙을 유지한다. 공개 저장소에 외부 코드를 넣기 전에는
라이선스와 출처를 확인한다.

### 1. 비용 계약과 짧은 샘플

권리가 확인된 1~5분 샘플을 정하고, 전사·번역·저장 단계별 예상 및 실제 비용
공식을 정의한다. 단계별 비용 합계가 상한을 넘으면 다음 유료 요청을 시작하지
않도록 설계한다.

### 2. 최소 수직 흐름

명령 하나로 `입력 → 일본어 전사 → 한국어 번역 → SRT → 비용 보고서`를 실행한다.
오류가 나면 단계·공급자 응답 범주·재시도 가능 여부를 명시적으로 반환한다.

### 3. 시간축과 품질 검사

원본 시간축 보존, 빈 큐·겹치는 큐·역전된 시간·유효하지 않은 SRT를 검사한다.
번역 단계 실패는 전사 자막을 덮어쓰지 않는다.

### 4. 장시간 입력 최적화

4시간 샘플에 대해 음성 구간 축소, 안전한 분할, 재개, 비용 상한 중단을 검증한다.
이 단계가 끝나기 전에는 5센트 목표나 누락률을 홍보하지 않는다.

### 5. 사용자 인터페이스

파이프라인의 비용·품질·복구 동작이 검증된 후 업로드, 작업 상태, 결과 다운로드
화면을 추가한다.

## GitHub 작업 규칙

- `master`는 검증된 상태만 유지한다.
- 각 단계는 `feature/`, `fix/`, `docs/` 접두사의 브랜치에서 작업한다.
- 커밋은 하나의 검증 가능한 변경을 나타내며, 원격에 푸시한다.
- 병합 전에는 해당 단계의 자동 검사와 비용 보고 형식을 확인한다.
