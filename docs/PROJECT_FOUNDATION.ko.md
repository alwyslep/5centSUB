# 5centSUB 프로젝트 기반 계획

## 목표와 성공 기준

- 권리를 보유하거나 처리를 허가받은 일본어 영상에서 한국어 자막을 만든다.
- 4시간 입력 영상의 전체 클라우드 비용을 미화 5센트 이하로 유지한다.
- 결과물은 표준 SRT이며, 자막 시간 범위와 문법을 자동 검증한다.
- 각 작업은 입력 식별자, 단계별 상태, 실패 사유, 사용량, 비용을 남긴다.

5센트는 목표치가 아니라 릴리스 차단 조건이다. 실제 사용량에 따른 비용 계산이
가능해지기 전에는 이 목표를 달성했다고 주장하지 않는다.

저작권자, 라이선스, 필요한 고지, 수정 내역을 먼저 기록한다.

## SNOS-295 과거 실험의 포렌식 기준선

다음 값은 5centSUB에서 실행한 결과나 현재 공급자 가격이 아니다. 외부 참고
프로젝트 `WhisperJAV-Cloud`의 2026-09-20 실험 산출물과 실행 기록을 대조한
**역사적 기준선**이며, 이 저장소에는 원본 미디어·원시 응답·키·사용량 로그를
복사하지 않는다.

| 실행 | 근거 수준 | 확인된 수치 | 해석 |
| --- | --- | --- | --- |
| 1차 Adaptive AQD | 원시 Google Batch 응답을 독립 합산 가능 | 입력 149,167, 출력 66,976 토큰 | 표준 단가(입력 $0.150/M, 출력 $0.600/M)에서는 $0.06256065 = ₩84.4569 (₩1,350/USD), Batch 50% 단가에서는 $0.031280325 = ₩42.2284 |
| 2차 Hybrid AQD | 실행 로그·세션 기록과 코드의 계산식은 존재하나 원시 사용량 응답은 없음 | ASR ₩48.5 + 번역 ₩19.6 = 총 ₩68.1, 2,199 큐 | 보고된 결과는 추적 가능하지만, 토큰 단위의 독립 재계산은 아직 불가능 |

첫 행의 원시 응답 파일은 외부 작업 트리의
`test_output\SNOS-295\SNOS-295_compact_asr_raw.json`이며, 1차 파이프라인은
명시적으로 이를 저장한다. 따라서 표준가 ₩84.5는 Batch 청구액이 아니라 동일
토큰을 표준가로 환산한 비교 수치이고, 해당 실행의 Batch 재계산값은 ₩42.2이다.

2차 Hybrid 파이프라인은 메타데이터만 `SNOS-295_hybrid_meta.json`에 저장하고,
ASR Batch 응답과 번역 사용량을 파일로 덤프하지 않는다. 코드는 수집한 토큰에
Batch ASR 단가(입력 $0.075/M, 출력 $0.300/M)와 번역 단가를 적용해 합계를
출력하므로, 실행 로그의 ₩48.5/₩19.6/₩68.1은 해당 실행 결과로 추적된다.
그러나 원시 Hybrid 응답·번역 usage가 없으므로, 이를 영수증 수준의 독립 검증
근거로 표현해서는 안 된다.

환율을 ₩1,350/USD로 고정해 비교하면 ₩68.1은 약 $0.05044다. 즉 이 과거
실험은 100원 예산에는 들어오지만, 이 프로젝트의 **$0.05 이하** 릴리스
차단 조건은 약 $0.00044 초과한다. 환율·가격·재시도 비용은 변하므로 이를
5센트 달성 증거로 사용하지 않는다.

향후 실제 공급자 실행은 Git에 원시 응답이나 사용량을 커밋하지 않되, 작업별
로컬 비공개 증적 묶음에 다음을 함께 보관한다: 원시 ASR 응답, 번역 요청별
입·출력 토큰 및 청구액, 모델·단가·환율의 스냅샷, 그리고 각 파일의 SHA-256
해시. 비용 보고서는 이 증적에서 재생성 가능해야 하며, 누계값만으로 실측
청구액을 주장하지 않는다.

## 처리 경계

새 구현은 로컬 ML 모델, GPU 추론, 사용자 컴퓨터의 음성 인식을 사용하지 않는다.
비용을 줄이기 위해 업로드 전 FFmpeg 등의 로컬 비-ML 미디어 준비는 허용한다.
전사·번역·화자 식별처럼 모델 추론이 필요한 단계는 클라우드 서비스에서만 실행한다.

API 키, 원본 영상·오디오, 생성 자막, 요청·응답 본문, 사용량 기록은 Git에 넣지
않는다. 테스트는 합성 또는 명시적으로 재배포 가능한 짧은 자료만 사용한다.

## 단계별 진행 순서

### 0. 기반 문서화

이 문서, README, 저장소 규칙을 유지한다. 공개 저장소에 외부 코드를 넣기 전에는
라이선스와 출처를 확인한다.

### 1. 비용 계약과 짧은 샘플

권리가 확인된 1~5분 샘플을 정하고, 전사·번역·저장 단계별 예상 및 실제 비용
공식을 정의한다. 단계별 비용 합계가 상한을 넘으면 다음 유료 요청을 시작하지
않도록 설계한다.

첫 구현은 실제 API를 호출하지 않는 Python CLI다. 모의 전사·번역 공급자로 비용
상한, 작업 상태 전이, SRT 무결성을 테스트하며, 이후 실제 공급자는 같은 인터페이스
뒤에 추가한다.

후보의 현재 가격과 사용 조건은
[`PROVIDER_RESEARCH.ko.md`](PROVIDER_RESEARCH.ko.md)에 기록한다. 공급자를
확정하기 전에는 실제 API 키를 요구하거나 유료 요청을 보내지 않는다.

### 2. 최소 수직 흐름

명령 하나로 `입력 → 일본어 전사 → 한국어 번역 → SRT → 비용 보고서`를 실행한다.
오류가 나면 단계·공급자 응답 범주·재시도 가능 여부를 명시적으로 반환한다.

### 3. 시간축과 품질 검사

원본 시간축 보존, 빈 큐·겹치는 큐·역전된 시간·유효하지 않은 SRT를 검사한다.
번역 단계 실패는 전사 자막을 덮어쓰지 않는다.

### 4. 장시간 입력 최적화

4시간 샘플에 대해 음성 구간 축소, 안전한 분할, 재개, 비용 상한 중단을 검증한다.
이 단계가 끝나기 전에는 5센트 목표나 누락률을 홍보하지 않는다.

### 5. 사용자 인터페이스

파이프라인의 비용·품질·복구 동작이 검증된 후 업로드, 작업 상태, 결과 다운로드
화면을 추가한다.

## GitHub 작업 규칙

- `master`는 검증된 상태만 유지한다.
- 각 단계는 `feature/`, `fix/`, `docs/` 접두사의 브랜치에서 작업한다.
- 커밋은 하나의 검증 가능한 변경을 나타내며, 원격에 푸시한다.
- 병합 전에는 해당 단계의 자동 검사와 비용 보고 형식을 확인한다.
